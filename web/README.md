# deChat web client

A React + TypeScript PWA for the deChat backend. Login, room list, real-time
chat over WebSocket, installable. This is the **base** client — calls, push,
and admin UI come later (see `../docs/CLIENT_NEXT_STEPS.md`).

## Stack

React 18 · TypeScript · Vite 5 · `vite-plugin-pwa` · React Router · TanStack
Query · Zustand · Tailwind CSS · native `WebSocket`. The typed API client is
**generated** from the backend's `openapi.json` via `openapi-typescript` +
`openapi-fetch`.

## Prerequisites

- Node 20+ (Node 24 used in development)
- pnpm 9+
- The deChat backend running on `http://localhost:8080` (e.g. `make docker-up`
  from the repo root)

## First-time setup

```bash
pnpm install          # installs deps (approves esbuild's build)
pnpm gen:api          # generates src/api/schema.ts from ../openapi.json
pnpm gen:icons        # generates placeholder PWA icons (run once)
```

`pnpm install` will succeed but pnpm blocks esbuild's postinstall by default.
The included `pnpm-workspace.yaml` allows it; if esbuild fails to run, run
`pnpm rebuild esbuild` (or `pnpm add -D @esbuild/<your-platform>`).

## Daily development

```bash
pnpm dev              # Vite dev server on http://localhost:5173
pnpm typecheck        # tsc --noEmit
pnpm build            # production build → dist/
pnpm preview          # serve the production build
```

The dev server proxies `/api`, `/openapi.json`, etc. to `localhost:8080`, so
start the backend first (`make docker-up` from the repo root) and the client
just works with no env config.

## Keeping the client in sync with the backend

The API contract is generated, never hand-written. When the backend changes:

```bash
# from the repo root
make openapi          # regenerate openapi.json from the Go server
cd web && pnpm gen:api  # regenerate src/api/schema.ts
pnpm typecheck        # surface any breaking changes
```

`src/api/schema.ts` is gitignored — it is always regenerated from the spec.

## How auth works

- `POST /api/v1/login` returns `{token, username, role}`.
- The token is stored in `localStorage` (key `dechat.auth`) and mirrored in a
  Zustand store.
- The API client injects `Authorization: Bearer <token>` on every request via
  a fetch middleware.
- The WebSocket passes the token as a `?token=` query parameter (browsers
  cannot set headers on the WS handshake).
- `ProtectedRoute` redirects unauthenticated users to `/login`.

## PWA / installability

The app registers a service worker (`vite-plugin-pwa`) that precaches the app
shell. API and WebSocket traffic is never cached. Use **Add to Home Screen**
on mobile or the install prompt on desktop to install it.
